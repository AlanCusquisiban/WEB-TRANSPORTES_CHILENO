3. PROPOSITO Y CONTEXTO DEL NEGOCIO LOGISTICO
================================================================================

En la empresa de transporte de carga pesada "Transportes Chileno E.I.R.L." (Lima, Peru):
Cada vez que un camion completa una ruta (por ejemplo Base San Martin de Porres al
Puerto del Callao, Lurin, Chorrillos o Chancay), el area de operaciones y finanzas
debe "liquidar el viaje" para:
  a) Determinar el consumo real de petroleo Diesel B5 S-50 segun kilometros,
     tonelaje de carga transportada, marca del motor y paradas intermedias.
  b) Calcular el gasto en peajes segun el numero de ejes del camion (concesiones
     Rutas de Lima, Lamsac, Norvial).
  c) Liquidar el viatico y bonificacion del conductor, o aplicar deducciones si
     hubo paradas indebidas o exceso de velocidad (>80 km/h reportado por GPS).
  d) Calcular impuestos peruanos (18% IGV, 4% de detraccion SPOT SUNAT) y la
     utilidad neta de la operacion.

4. MALOS OLORES DE CODIGO (CODE SMELLS) DETECTADOS
================================================================================

El codigo actual en script.js (§16) fue escrito con malas practicas deliberadas
para que el alumno pueda sustentarlas usando los estandares de Martin Fowler
("Refactoring") y Robert C. Martin ("Clean Code"):

--------------------------------------------------------------------------------
Smell 1: Metodo Demasiado Largo / Objeto Dios (Long Method / God Function)
--------------------------------------------------------------------------------
* Que ocurre: La funcion 'liquidarRutaYCalcularCostosOperativos' tiene mas de 120
  lineas y asume demasiadas responsabilidades simultaneas:
  - Valida datos de entrada mediante alert().
  - Busca entidades en arrays globales.
  - Ejecuta formulas matematicas de consumo de diesel.
  - Clasifica tarifas de peajes con switch anidados.
  - Evalua penalidades al chofer.
  - Calcula impuestos peruanos (IGV, Detraccion).
  - Concatena cadenas HTML y modifica el DOM directamente.
* Principio violado: Principio de Responsabilidad Unica (SRP - Single Responsibility Principle).

--------------------------------------------------------------------------------
Smell 2: Numeros Magicos (Magic Numbers)
--------------------------------------------------------------------------------
* Que ocurre: En el codigo existen valores literales quemados ("hardcoded") sin
  nombre ni constante que explique su significado de negocio:
  - 12.5  -> Rendimiento base en km/galon de un camion de carga.
  - 1.28  -> Coeficiente de incremento de consumo por peso de carga.
  - 18.65 -> Precio promedio del galon de diesel B5 S-50 en soles (S/.).
  - 0.75  -> Galones adicionales consumidos por arranque en cada parada.
  - 6.50  -> Tarifa oficial de peaje por eje vehicular en garitas de Lima.
  - 45.0  -> Viatico basico en soles para rutas locales cortas.
  - 85.0  -> Viatico para rutas intermedias (>50 km).
  - 140.0 -> Viatico para rutas de largo recorrido (>100 km).
  - 0.015 -> Tasa del seguro de carga vehicular (1.5%).
  - 1.45  -> Margen de sobreprecio sobre costo operativo para flete (45%).
  - 0.18  -> Tasa del Impuesto General a las Ventas (IGV 18%).
  - 0.04  -> Tasa de Detraccion SPOT SUNAT para transporte de carga (4%).

--------------------------------------------------------------------------------
Smell 3: Complejidad Ciclomatica y Anidamiento Excesivo (Arrow Anti-Pattern)
--------------------------------------------------------------------------------
* Que ocurre: Hay piramides de 'if/else' anidados con 4 y 5 niveles de profundidad:
  if (!viajeId) { ... } else { for(...) { if(...) { ... } } if (!r) { ... } else { ... } }
* Impacto: Alta dificultad de lectura, riesgo de bugs y casi imposible de testear
  con pruebas unitarias aisladas.

--------------------------------------------------------------------------------
Smell 4: Codigo Duplicado (Duplicated Code)
--------------------------------------------------------------------------------
* Que ocurre: La busqueda de vehiculo y conductor repite bucles 'for' manuales
  en lugar de utilizar funciones de orden superior como .find(), y los factores de
  marca repiten formulas de multiplicacion directa.

--------------------------------------------------------------------------------
Smell 5: Nombres Cripticos de Variables (Cryptic / Meaningless Naming)
--------------------------------------------------------------------------------
* Que ocurre: Nombres opacos que no revelan intencion:
  - 'd_km'     (deberia ser: distanciaKilometros)
  - 'p_ton'    (deberia ser: capacidadCargaToneladas)
  - 'c_gal'    (deberia ser: galonesDieselConsumidos)
  - 'costo_comb' (deberia ser: costoTotalCombustible)
  - 'n_ejes'   (deberia ser: numeroEjesVehiculo)
  - 'r', 'v', 'd' (deberian ser: viajeSeleccionado, vehiculoAsociado, conductorAsociado)

--------------------------------------------------------------------------------
Smell 6: Envidia de Atributos y Acoplamiento Fuerte (Feature Envy & Tight Coupling)
--------------------------------------------------------------------------------
* Que ocurre: La funcion accede y muta de forma directa las estructuras crudas de
  los arrays globales 'journeyHistoryData', 'vehiclesData' y 'driversData'.
  Si la estructura de estos arrays cambia en el futuro, la liquidacion se rompe.

--------------------------------------------------------------------------------
Smell 7: Falta de Separacion entre Dominio y Presentacion (Mixed Concerns)
--------------------------------------------------------------------------------
* Que ocurre: El calculo matematico financiero esta fuertemente acoplado con la
  generacion de HTML (`resultsPanel.innerHTML = ...`) y con el framework visual.
  No se puede reutilizar el calculo en Node.js, en una API REST o en tests unitarios.

Aqui tienes la version refactorizada que puedes presentar como tu propuesta de mejora:

```javascript
/* =========================================================================
   MODULO REFACTORIZADO: LIQUIDACION LOGISTICA CLEAN CODE
   ========================================================================= */

const CONSTANTES_LOGISTICA = Object.freeze({
  RENDIMIENTO_BASE_KM_GALON: 12.5,
  FACTOR_INCREMENTO_PESO: 0.28,
  PESO_REFERENCIA_TON: 25.0,
  CONSUMO_EXTRA_POR_PARADA: 0.75,
  PRECIO_DIESEL_DEFECTO: 18.65,
  TARIFA_PEAJE_POR_EJE: 6.50,
  TASA_SEGURO_CARGA: 0.015,
  FACTOR_FLETE_COMERCIAL: 1.45,
  TASA_IGV: 0.18,
  TASA_DETRACCION: 0.04
});

const FACTORES_EFICIENCIA_MOTOR = Object.freeze({
  'Volvo': 1.05,
  'Scania': 1.05,
  'International': 1.12,
  'Hino': 1.08,
  'Mercedes-Benz': 1.06,
  'Default': 1.06
});

// 1. Calculador Puro de Combustible
function calcularConsumoCombustible(distanciaKm, capacidadTon, marca, cantidadParadas, precioGalon) {
  const consumoBase = (distanciaKm / CONSTANTES_LOGISTICA.RENDIMIENTO_BASE_KM_GALON) *
                      (1 + (capacidadTon / CONSTANTES_LOGISTICA.PESO_REFERENCIA_TON) * CONSTANTES_LOGISTICA.FACTOR_INCREMENTO_PESO);
  
  const factorMarca = FACTORES_EFICIENCIA_MOTOR[marca] || FACTORES_EFICIENCIA_MOTOR['Default'];
  const galonesAjustados = (consumoBase * factorMarca) + (cantidadParadas * CONSTANTES_LOGISTICA.CONSUMO_EXTRA_POR_PARADA);
  const costoTotal = galonesAjustados * precioGalon;

  return {
    galones: Number(galonesAjustados.toFixed(2)),
    costo: Number(costoTotal.toFixed(2))
  };
}

// 2. Calculador Puro de Peajes
function calcularPeajesRuta(destino, numeroEjes) {
  let garitas = 1;
  const destinosDobleGarita = ['Callao', 'Chorrillos', 'Lurin', 'Villa El Salvador', 'Chancay', 'Huachipa'];
  
  if (destinosDobleGarita.some(d => destino.includes(d))) garitas = 2;
  else if (destino.includes('Pisco')) garitas = 4;

  const costoTotal = garitas * (numeroEjes * CONSTANTES_LOGISTICA.TARIFA_PEAJE_POR_EJE);
  return {
    garitas,
    costo: Number(costoTotal.toFixed(2))
  };
}

// 3. Calculador de Viaticos y Rendimiento del Conductor
function calcularCompensacionConductor(distanciaKm, cantidadParadas, viajeId, aplicarPenalidades = true) {
  let viatico = 45.0;
  if (distanciaKm > 100) viatico = 140.0;
  else if (distanciaKm > 50) viatico = 85.0;

  const bonoBase = 50.0;
  let penalidad = 0.0;

  if (aplicarPenalidades) {
    if (cantidadParadas >= 3) penalidad += 25.0;
    if (viajeId === 'R-104' || (distanciaKm > 60 && cantidadParadas > 2)) penalidad += 100.0;
  }

  const neto = Math.max(0, viatico + bonoBase - penalidad);
  return { viatico, bono: bonoBase, penalidad, neto };
}

// 4. Orquestador de Dominio Financiero
function liquidarViajeRefactorizado(viaje, vehiculo, conductor, precioDieselCustom = null) {
  const precioDiesel = precioDieselCustom ? Number(precioDieselCustom) : CONSTANTES_LOGISTICA.PRECIO_DIESEL_DEFECTO;
  const distanciaKm = viaje.km || 40.0;
  const capacidadTon = vehiculo?.capacidad || 20.0;
  const ejes = vehiculo?.ejes || 4;
  const paradas = (viaje.paradas?.match(/\d+/) || [0])[0];

  const combustible = calcularConsumoCombustible(distanciaKm, capacidadTon, vehiculo?.marca, Number(paradas), precioDiesel);
  const peajes = calcularPeajesRuta(viaje.destino, ejes);
  const chofer = calcularCompensacionConductor(distanciaKm, Number(paradas), viaje.id);

  const subtotal = combustible.costo + peajes.costo + chofer.viatico + Math.max(0, chofer.bono - chofer.penalidad);
  const seguro = subtotal * CONSTANTES_LOGISTICA.TASA_SEGURO_CARGA;
  const costoOperativoTotal = subtotal + seguro;

  const fleteComercial = costoOperativoTotal * CONSTANTES_LOGISTICA.FACTOR_FLETE_COMERCIAL;
  const igv = fleteComercial * CONSTANTES_LOGISTICA.TASA_IGV;
  const detraccionSunat = (fleteComercial + igv) * CONSTANTES_LOGISTICA.TASA_DETRACCION;
  const utilidadNeta = fleteComercial - costoOperativoTotal;

  return {
    viajeId: viaje.id,
    distanciaKm,
    combustible,
    peajes,
    chofer,
    costoOperativoTotal: Number(costoOperativoTotal.toFixed(2)),
    fleteComercial: Number(fleteComercial.toFixed(2)),
    igv: Number(igv.toFixed(2)),
    detraccionSunat: Number(detraccionSunat.toFixed(2)),
    utilidadNeta: Number(utilidadNeta.toFixed(2)),
    margenPorcentaje: Number(((utilidadNeta / fleteComercial) * 100).toFixed(1))
  };
}
```

8. PREGUNTAS Y RESPUESTAS PARA LA SUSTENTACION DE LA TAREA
================================================================================

P: ¿Por que tener metodos largos es malo si el codigo ya funciona?
R: Porque un metodo largo viola el Principio de Responsabilidad Unica (SRP), es
   dificil de entender para nuevos desarrolladores, no permite reutilizacion de
   sub-calculos (como calcular peajes en otras vistas) y complica la escritura de
   pruebas unitarias automatizadas.

P: ¿Cual es el beneficio principal de eliminar Numeros Magicos?
R: Mantenibilidad inmediata. Si mañana el Ministerio de Transportes sube el peaje
   de S/. 6.50 a S/. 7.00 o SUNAT cambia la detraccion, en el codigo original
   habria que buscar ese "6.50" en multiples lineas arriesgando olvidar alguna.
   En el codigo refactorizado, solo se modifica una constante centralizada.

P: ¿Como garantizamos que la refactorizacion no rompio nada?
R: Mediante los 4 Casos de Prueba (Regression Testing). Al comparar los outputs
   de la version original con la refactorizada usando los mismos datos de entrada,
   los valores de combustible, peajes y costos coinciden al 100% hasta el centimo.
